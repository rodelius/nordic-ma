Examples:

- EUR fund buying Swedish SEK asset: buyer may need EUR → SEK.

- Swedish seller owned by EUR fund: seller may need SEK → EUR.

- Swedish corporate buying USD asset: buyer may need SEK → USD if funding the purchase from SEK.

- EUR infrastructure fund buying Norwegian NOK asset: buyer may need EUR → NOK.

- Sponsor seller exiting Norwegian asset: seller may need NOK → EUR/USD, depending on fund denomination.

Lower priority:

- Finnish EUR-to-EUR deals unless rates/debt relevance is high.

- Danish DKK/EUR deals unless rates/debt relevance is high.

5. The development sequence I recommend

Build the user interface using v0.

Start with synthetic deals to create the opportunity radar, deal detail screen and mobile views. Verify usability before developing the intelligence engine.

Create a GitHub repository for the web app.

Keep your existing SwiftUI project as a reference rather than deleting it. Its potential to become a mobile front end can be reconsidered later.

Connect Codex Cloud and build the application in testable increments.

Start with the database and transaction lifecycle; next implement source ingestion, deduplication, event detection, and finally FICC relevance scoring.

Deploy a working application to Vercel.

Test it from your Mac and your iPhone. An iOS home-screen PWA can support web push notifications on iOS 16.4 or later, without App Store distribution.


Validate the intelligence before automating alerts.

Use a historical transaction set to check whether the system detects important milestones, suppresses duplicates, identifies genuine FICC exposures and avoids fabricated conclusions.

The first milestone should be a functioning deal radar with evidence-backed alerts, rather than trying to build all the advanced quantitative advisory tools immediately.
